# Phase 1（MVP）実装

## 対象

- `package.json` / `tsconfig.json` / `next.config.ts` / `postcss.config.mjs` / `vitest.config.ts`
- `src/engine/`：勘定科目マスタ、仕訳の採点・診断、勘定残高・試算表・財務諸表の集計
- `src/content/`：キャラクター・商品、講義9本、勘定科目の説明、取引イベント23種
- `src/game/`：ゲーム状態の型、進行ロジック（1日の予定・選択・採点・日末・月末・Lvアップ）、端末内セーブ
- `src/components/`：画面一式（タイトル、店内シーン、講義、仕訳入力、帳簿の可視化、簿記の書、日末・月末・Lvアップ）
- テスト：`src/engine/engine.test.ts`、`src/game/game.test.ts`

## 変更内容

- Next.js 16.4 + React 19.3 + TypeScript 7 + Tailwind 4.3 で新規構築
- Lv1（露店）〜Lv2（小さな店舗）を遊べる形で実装
  - Lv1：簿記の基礎、設立と預金、仕入と売上（三分法）、店の費用
  - Lv2：掛け取引、返品、前払金・前受金（特注の杖クエスト）、運び賃と送料、現金過不足
- 仕訳入力はカード式（タップで配置、PCはドラッグも可）。ヒント3段階、答えは一度挑戦してから表示
- ミスの診断（未記入・貸借逆・貸借不一致・科目違い・金額違い）と、行ごとの理由の説明
- 帳簿の可視化（貸借対照表・損益計算書をブロックの高さで表示し、動いた科目を光らせる）
- 月末に残高試算表と2問のクイズ。日末にS〜Cの評価と豆知識
- ドット絵はコードで描画（左右対称の絵は左半分を鏡写し）、効果音はWebAudioの矩形波

## 理由

SPEC.md の Phase 1。「楽しく学べるか」を軸に、経営判断の意味（ツケ・広告・在庫切れ）、
数日にまたがるクエスト、コンボ、成長条件の見える化を入れた。

## 検証

- ランダムな経営判断で60日×8パターンを通しプレイするテストで、貸借一致、未習得科目を使わないこと、
  帳簿の売掛金・買掛金とゲーム内のツケ残高の一致、現金・預金・在庫が負にならないことを確認
- ブラウザで実際のボタン操作による通しプレイ、セーブからの再開、Lvアップ、スマホ幅390pxでの横はみ出しなしを確認

## 試行錯誤の記録

- 通しプレイのテストで、現金不足のとき光熱費イベントで選択肢が全部押せずに止まる不具合を発見
  → 普通預金での支払いを追加し、全選択肢が選べないときは「見送る」を自動で足す仕組みにした
- ブラウザでの確認で、空欄の記帳まで減点していたため信用が0まで落ちることが判明
  → 空欄は注意のみ、ミスは−2、ミス後に自力で正解したら+1に調整
- 三分法では売れ残りの仕入も費用になるため、序盤に赤字表示になる
  → 月末クイズと損益計算書に「決算で調整する」の注記を追加（決算フェーズへの伏線）

## /simplify による整理

- 重複を共通化：数値の書式 `fmt`（engine/format.ts）、仕訳の組み立て `entry`、合計 `sumAmounts`、`dayInMonth`、`itemsForLevel`、`sideWithPos`、`trialBalanceTotals`
- 借方・貸方の符号ルールを `homeSide` に一本化（-0 の補正が不要になった）
- 初日の予定を講義データ（`opening` フラグ）から組み立てる形に。特注クエストの並べ替え処理を削除
- 売上累計・今日の講義・来客予定・Lvアップ条件（`LEVEL_UP`）をロジック側に集約し、画面と条件の食い違いを防止
- 保存は400msまとめて行い、ページを閉じる前と、タイトルへ戻るときに確実に保存
- 仕訳帳は最新50件＋「もっと見る」。ドット絵は `memo` で描き直しを省略
- 見送り：ミス履歴（Phase 4 の苦手ドリルで使う）、予定キューの型付け・ツケ残高を帳簿から導出・損益の配置をエンジン側へ（セーブ形式の変更を伴うので Phase 2 着手時に実施）
