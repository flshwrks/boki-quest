# 棚の表示・朝の仕入れ注文・キャラクターの動き・実績

## 対象

- `src/components/Scene.tsx`（棚の2列表示）、`LedgerViz.tsx`（長い科目名のはみ出し）
- `src/components/OrderPanel.tsx`（新規）、`Panels.tsx`、`src/game/logic.ts`（startOrder / orderPreview / afterResult）、`src/game/types.ts`
- `src/components/Sprite.tsx`、`ui.tsx`、`src/app/globals.css`（まばたき・待機の揺れ・羽ばたき）
- `src/content/achievements.ts`（新規）、`src/components/GameApp.tsx`（お知らせ・獲得数）、`BookModal.tsx`（実績ページ）

## 変更内容

- 棚：商品が4つ以上なら2列にし、商品名・在庫数・小さなアイコン（最大8個）を1枠に収める
- 朝の仕入れ注文：開店前に、商品・数量・支払い方（現金／普通預金／掛け）を選んで注文できる。注文ごとに仕訳を書き、終わったら朝の画面に戻る。消費税を習ったあとは税込で計算し、お金が足りない注文はできない
- キャラクターの動き：目のドットを差し替えたコマでまばたき、2コマの待機の揺れ、妖精ピピの羽ばたき。動き出しはキャラクターごとにずらす。動きを減らす設定では止める
- 実績（やり込み要素）：20種。ふだんのプレイの結果から判定し、獲得するとお知らせ。ヘッダーに獲得数、簿記の書に実績ページ（未獲得はヒントだけ表示）
- 帳簿の図で、長い科目名（減価償却累計額など）が枠からはみ出していたのを修正。Lv5で「次の成長は次のアップデートで」と出ていた文言を修正

## 理由

ユーザーの要望：商品がふえると棚からはみ出す／エーテルを仕入れる手段がなく品切れが多い／キャラクターに小さな動きがほしい／やり込み要素はこちらで考えてほしい（ゲームを複雑にしすぎない）。
仕入れは、別画面の「仕入れモード」にせず、朝の画面の一欄にとどめて操作を増やしすぎないようにした。実績も、新しい遊び方は足さず、ふだんのプレイで自然に集まるものだけにした。

## 検証

- テスト30件（注文して記帳すると在庫がふえて朝に戻ること、通しプレイで店の成長や決算の実績が取れること、を追加）
- ブラウザで、Lv5の棚（6商品が2列で収まる）、注文の欄、実績のお知らせ（古いセーブで17件がまとめて解除）、帳簿の図のはみ出し解消を確認

## /simplify による整理

- 実績の判定を、画面の副作用から進行の処理（update / commit を通るたびに withAchievements）へ移した。審査の満点など、一瞬だけ成り立つ条件も取りこぼさない。お知らせは実績の数が増えたときだけ出す（セーブを読み込んだときは出さない）
- 「記帳後に朝へ戻る」フラグ（returnToMorning）を廃止し、最後の記録が朝の注文かどうかで判断する
- 消費税の付与と残高チェックを prepareTx に、仕訳入力の開始を txSession にまとめ、イベントと朝の注文で共通にした
- purchaseTx の支払い方を「現金／普通預金／買掛金」の1引数にした。在庫が最も少ない商品と数量の候補は events.ts の lowestStockItem / orderQtys を共用する
- 注文欄のボタンを Btn のチップ型にした（効果音・フォーカス枠・aria-pressed がつく）。数量は候補の何番目かで持つ
- 店の成長の実績4つを LEVELS の店名から生成する。全勘定科目カードの一覧（ALL_CARDS）は accountInfo.ts の1か所にまとめた
- まばたきは「閉じた目のコマ」だけを重ねて点滅させる形にし、動き出しのずれは CSS 変数 --sprite-delay で一度だけ渡す
- 残高チェックは、払う額が0なら帳簿を集計しない
- 見送り：templateId の型付け（既存のイベント全体に及ぶため）、アニメーション定義表の統合（動く部位がまだ2種類なので）
